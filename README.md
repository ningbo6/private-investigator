# 公司侦探

一个只用**元宝搜索 SearchPro**获取外部证据的本地公司公开信息调查台。

## 能查什么

先进行主体前置检查，找到名称线索后再开展五维检索。概览最多 6 次，深度调查最多 12 次：

1. 业务与产品：主营业务、产品体验、客户与交付
2. 经营与财务：收入、利润、现金流和持续经营
3. 技术与创新：研发、专利、技术落地
4. 风险与合规：监管司法、质量、投诉和整改
5. 组织与责任：治理、员工保障、环境与社会责任

主体检查不计入雷达图。雷达图以方向 ID 对应 DeepSeek 的有效内容可信度评分，固定 0–100 分；引用待核、评分失败和缺失值留空，不转换为零分。去重线索数量、调查状态和重点方向在图例中独立展示，数量不参与评分。旧报告没有有效模型评分时同样留空。

“指标”是调查维度，不是评分项。系统不会把搜索条数、负面关键词或媒体数量换算成公司好坏分。

## 启动

```bash
python3 server.py 8765
```

然后打开 <http://127.0.0.1:8765/>。服务只绑定 loopback，只允许同源浏览器请求。

### Docker 部署（更新代码自动重启）

需要已安装 Docker Desktop。首次启动或修改依赖镜像配置时执行：

```bash
docker compose up -d --build
```

然后打开 <http://127.0.0.1:8765/>。Compose 将容器端口只映射到本机，SQLite 数据保存在命名卷 `company_detective_data`；`.env` 仅作为运行时密钥注入，不会复制进镜像。

开发期间，项目目录以只读卷挂载到 `/app`。容器入口每 2 秒检查后端模块、`tools/verify_wsa.py` 和前端资源；文件稳定保存 2 秒后自动重启后端。正在进行的调查会先完成（最多等待 360 秒）。容器异常退出由 Compose `restart: unless-stopped` 自动拉起。查看状态：

```bash
docker compose ps
docker compose logs -f company-detective
```

停止服务（不删除数据卷）：

```bash
docker compose down
```

Docker Desktop 必须保持运行；Docker 引擎再次启动时，未被手动停止的容器自动恢复。电脑休眠期间服务暂停。修改 `.env` 后执行 `docker compose up -d --force-recreate`；修改 Dockerfile 或 `docker-entrypoint.sh` 后执行 `docker compose up -d --build`。不要同时运行宿主机的 `python3 server.py`，两者使用同一个 8765 端口。

构建默认使用清华 Debian/PyPI 镜像（保留 HTTPS 和 Debian 签名校验）。可通过构建参数 `DEBIAN_MIRROR=https://deb.debian.org`、`PYPI_INDEX=https://pypi.org/simple` 切回官方源；这些仅用于安装软件，不是公司调查的搜索来源。

本次部署已将原数据库完整备份到 `.backups/docker-migration-*.sqlite3` 并迁入 `1024_company_detective_data` 数据卷。容器启动后新记录只写入数据卷；原项目根目录数据库作为迁移前副本保留。不要执行 `docker compose down -v`，该选项会删除数据卷。

Docker 内置 Tesseract 简体中文/英文 OCR。更新后执行 `docker compose up -d --build --wait` 安装依赖；仅热重载代码不会安装 OCR。状态接口的 `ocr_info` 展示实际可用引擎。截图仅在本机容器临时目录处理，完成或失败后删除；不调用外部 OCR、元宝或 DeepSeek。支持 PNG/JPEG、最大 5 MB、单边不超过 12000 且不超过 3000 万像素，45 秒超时；模糊或复杂排版需人工校对。

凭据读取自环境变量或项目根目录 `.env`，不会发到前端。外部检索入口只有 `tools/verify_wsa.py` 的 `search()`，并通过 `engine.py` 统一调用。

## 功能

- 公司调查：公司全称、别名、官网域名、时间范围
- 证据卡：元宝摘要、原文链接、域名、来源类型、主体文字匹配、待核风险词
- 主体边界：同名或无关结果显示为“主体未匹配”，不计入名称匹配结论
- 历史报告：本地 SQLite 保存报告和元宝搜索缓存
- 双公司对比：比较本次元宝搜索覆盖，不生成排名
- 补充调查：监管公开信息、反向核查、披露平台，仍只调用元宝搜索
- 复查清单：强制实时重查，生成新增、消失和摘要变化；失败或部分结果不会覆盖可靠基线
- 报告导出：JSON 和 Markdown
- 本地调用状态：缓存命中、搜索尝试次数、RequestId

macOS 直接运行时优先使用本机 Vision 二进制 `tools/ocr_image`，图片只在本机识别；识别结果不会自动提交搜索，由用户核对候选名称并点击确认后自动发起元宝搜索。

## 证据边界

公开搜索摘要是线索，不是完整尽调。使用时应回到原文核对：

- 主体：统一社会信用代码、申请人/被申请人、子公司和同名主体
- 时间：公告日期、会计期间、案件和召回状态
- 技术：专利号、授权/有效状态、产品对应关系
- 风险：案号、金额、当事人角色、整改和结案状态
- 组织：匿名评价样本、职位、地点和时间

“元宝搜索没有返回”不等于事实不存在；企业自述、媒体转载、社区内容也不会自动升级为独立证明。


## 自动深度调查 v4.1

将调查问题写入“你想查清的问题”，选择“自动深度调查”：

- 第 1 轮：主体前置检查，无名称线索或请求失败则停止。
- 第 2 轮：五维概览。按问题选最多 3 个重点方向，其余做基础检索。
- 第 3 轮：根据首轮证据中的作品名、指标或事件追查；不再将整段会议宣传标题作为游戏体验问题的搜索词。
- 第 4 轮：每个重点方向追加独立评价、反证、处理结果或权威检索回退，总预算最多 12 次。
- 模型材料按具体问题关键词排序，每个候选来源簇最多 2 条、每问题最多 8 条，避免同源宣传占满输入。
- 交叉验证按“指标 + 期间 + 单位 + 口径”比对；同域、同源转载和相似摘要不算独立印证，冲突只标记为待核。

## 每日自动复查 v4.1

报告加入“复查清单”后，默认不会自动启用。选择北京时间并开启后，服务进程每 20 秒检查一次到期任务：

- 基础报告最多 6 次元宝搜索；深度报告最多 12 次。
- 失败或部分失败不覆盖基线；失败提醒会保存到提醒中心。
- 成功复查才比较新增、未返回和摘要变化；同源/纯排序变化尽量去重。
- 无变化不提醒；变化写入本地提醒中心，可标记已读；页面打开且浏览器授权时可弹桌面通知。
- 系统休眠或服务停止期间不会补跑所有历史天数；恢复后最多执行一次到期任务，避免集中消耗额度。

自动复查只在本机服务运行时调度，未注册外部 cron、短信或邮件。

## v4.1 检索修复与验证

- 对真实观测到的 `RequestId + Query + Version=standard` 且省略 `Pages` 的响应，仅在查询回显一致、无 API 错误时识别为空结果；畸形响应仍报错。
- 权威站点为空或结果域名不匹配时，在 12 次预算内用元宝搜索放宽追查，并展示目标域名匹配数；请求完成不等于证据充分。
- 同配置任务重新加入完整报告时可更新旧的失败/部分成功基线；内容比较忽略纯空白和顺序差异，减少重复提醒。
- 单元测试：先安装 OCR 图片校验依赖 `python3 -m pip install Pillow==12.2.0`，再运行 `python3 -m unittest discover -s tests -q`。
- 隔离提醒流程：`python3 tools/verify_monitoring_isolated.py`，使用合成数据和临时数据库，不表示真实企业事件。
- 真实查询与后台定时器验证记录：`output/authority-fix/验证记录.md`。真实复查未发生变化，变化与失败分支另用隔离测试验证。

## DeepSeek 内容可信度 v4.2

深度模式在元宝搜索完成后调用 DeepSeek，对每个子问题生成具体结论、0—100 内容可信度、引用摘句、评分理由和证据局限。评分不等于公司评级、游戏体验评分或真实概率。缺证显示“未评分”，不是 0 分；模型失败不影响查看原始搜索结果，也不会用规则分伪装成模型分。

后端读取项目 `.env`（不传到浏览器）：

```dotenv
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-flash
LLM_API_KEY=<在本机填写你的 DeepSeek 密钥>
```

2026-10-24 实测请求模型别名 `deepseek-v4-flash` 可用，响应实际模型为 `deepseek-flash`，模型列表名称为 `DeepSeek-V4.1-Flash`。报告保留请求模型、实际模型、RequestId、用量、输入摘要哈希和量表版本，不冒充固定不可变版本。

- 外部检索仍仅元宝搜索。公司问题和每个子问题最多 8 条搜索材料（摘要每条最多 2200 字符）发送到 DeepSeek 官方接口，模型不提供额外事实来源。
- 五项各 0—20：问题相关性、直接支持、来源质量、细节口径、一致与独立性。维度由模型评估，程序只校验范围并求和。
- 引用必须来自实际发送的材料 ID，且摘句必须在该材料标题或摘要内逐字存在。结构或引用无效最多纠正重试一次，仍无效则不显示分数。逐字匹配只证明引用存在，不证明模型结论必然正确。
- 相同证据和评估规则复用本地评分缓存；真实变化的摘要重新评分。自动复查仍以搜索内容变化提醒，不因模型分数抖动而提醒。
- “游戏/餐饮做得怎么样”分别检索该业务的产品运营、经营表现、评价与投诉，不再退回无关专利模板。拆解仍为透明规则，不是通用大模型规划。
- 历史报告保持原样；重新调查才能生成新评分。五维概览暂不调用模型评分。

维度版本变更时，旧复查基线不会被自动覆盖，也不把改版造成的搜索差异当作企业变化；请打开新报告并明确加入复查以更新基线。

### 五维内容评分与专利专项

五个方向各自按元宝检索摘要由 DeepSeek 评估；基础调查也可评分，不再只评重点追查的三个问题。雷达图展示各方向 DeepSeek 内容可信度分数，去重数量和调查状态仅在图例中辅助展示。

技术与创新另展示五项专利证据核对：申请人与权属、专利身份与类型、法律状态与时效、技术与问题相关性、应用与转化。每项给出模型评分、引用、依据和证据缺口。专项分不加总为专利价值，也不与技术方向分重复计分。

统一量表为相关性、直接支持、来源质量、细节口径、一致与独立性，每项 0–20。只允许引用本方向输入材料，引用与摘要对齐后方可展示分数。材料不足显示“未评分”，不以品牌、数量或申请公告推断技术领先、授权有效或商业成功。历史报告保留原有评分，新调查使用新版量表。

### 问题优先的调查报告

新版报告先展示结论、逐方向证据摘句与来源、疑似分歧和尚未查明事项。雷达图与可信度评分收纳在默认折叠的辅助区。历史报告保持原样，不补造结论。

追查器根据前轮材料识别：无相关证据、业务不匹配、专利号/法律状态缺失、实际量产证据缺失、财务期间口径缺失、来源单一和数值疑似冲突。每个重点问题在预算内做一次缺口追查，保留触发原因、父证据和追查后缺口；未发现这些结构性缺口时执行反证检索。不声称这是无限轮自主研究，也不将补齐结构字段当作事实确认。

输入范围检查在外部搜索前执行：拦截可识别的时政、个人生活、联系方式和个人调查；无法识别为组织的名称要求填写工商全称。此为保守规则，不是覆盖所有表达的语义分类器；已知品牌可用简称，其他品牌可能需要全称。

### 默认公司简报（v5.1）

只填写公司名称即可，具体问题为可选项。未填写问题时先做主体检查与五维基础检索，再由实际返回材料发现疑点：疑似冲突、风险事件线索、专利法律状态、财务口径、来源独立性或缺证。按明确优先级选最多三个方向深入；记录触发依据、父证据和未覆盖的候选。风险关键词只是追查线索，不是定罪或事实确认。

最终简报保留全部五维概况与引用，不因只深入三个方向而隐藏其他维度。专利详细核对与五维可信度评分继续放在辅助区。填写具体问题时仍可执行原有问题定向流程。API 默认模式为 deep；双公司概览显式使用 overview。主体检查＋五维＋最多六次追查，总预算不超过12次。

### 具体疑点闭环（v5.2，当前版本）

默认输入公司名称，先全面检索五维，再从初始材料提取具体说法、事件或专利号。每条疑点保存原始摘句及来源、触发原因、追查词及父证据、后续新增线索、独立评估的结论与引用、仍未查明事项。流程完成不代表事实已确认；新增链接也不等于独立来源。

名称未在同句出现的片段被单独隔离展示，不送入五维或疑点结论的模型输入。该规则保守：可能排除上下文省略主语的有效资料，但不会将其直接推断为公司事实；名称同句出现也不是工商主体或责任归属认证。

单份历史报告可通过 `http://127.0.0.1:8765/?report=报告ID` 直接打开。提交演示包的离线页面仅回放真实查询结果，不假装重新搜索。Docker 版不宣传截图查证已完成；每日复查依赖运行中的本机服务，提醒指搜索快照变化。

### 报告阅读顺序更新

页面按主体检查、简报节选、疑点追查、逐方向完整结论与证据、辅助评分、主体不明材料、折叠检索过程排列。来源按网址合并（只去掉片段标记，保留查询参数），同一网址的不同摘要仍可展开；完全相同的长摘要归为一组，不将不同链接视作独立印证。相似但不同的转载不自动合并，避免误删反证。已识别争议的引用并排展示，没有可比冲突时明确说明，不制造正反方。

专利展示按申请人、专利身份、法律状态、技术与业务关系、应用转化排列，各项保留原模型依据与未知。五维雷达轴固定显示，方向元数据不全也不删轴；没有有效模型评分显示“暂无评分”。SVG 内为名称和分数预留边距，避免窄报告列裁切标签。

前端回归：`node tests/test_radar.js` 与 `node tests/test_report_presentation.js`。页面排序与分组不额外触发搜索或改写历史报告结论。

### 截图确认即调查

OCR 成功后从识别文本提取公司候选，用户可选择并修改名称，点击“确认公司并开始调查”即可自动发起五维简报与疑点追查（最多 12 次元宝搜索）。不需复制粘贴，不在识别成功时自行消耗搜索额度。仅提交确认后的公司名称，不提交整张截图或整段 OCR 文本，清除上一家公司的别名、域名及问题。候选只是规则提取，不代表主体认证；未提取到名称时保留手动补充入口，空白图不允许确认。

回归验证：`node tests/test_ocr_confirmation.js`。
